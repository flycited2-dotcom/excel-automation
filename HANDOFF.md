## Сессия 2026-06-15 — автоматизация ежедневного прогона + дедуп расходников

### Полный автозапуск (`daily.py`, Планировщик Windows)
Шаги: **0** забрать прайс ТЛТ из почты → **1** скачать прайс поставщика →
**2** трансформация → **3** отправка в Telegram. Шаг 0 некритичный: при сбое

- тема **«Прайс_Опт_авторассылка»** — для клиентской рассылки (лишние товары
  убраны); **именно её берём** (`subject_contains` в secrets.json).
- тема «Прайс_Опт_внутрн» — внутренний прайс, все товары (НЕ берём).

Авторизация — Gmail IMAP по паролю приложения (нужна 2FA). Все креды в
`secrets.json` (в git НЕ коммитится): блоки `email`, `supplier`, `telegram`.

### Формат выгрузки 1С отличается от ручных файлов
Появилась колонка N «Изображение», цена уехала в **колонку O**.
`read_tlt_price` теперь ищет колонку цены по заголовку «Цена» (не по индексу).

### Дедуп расходников ТЛТ/СплитХаб (спека `docs/.../2026-06-15-...`)

после расходников (`group_positions` 2.1/2.2/2.3). Холодильники капельные/ТВ →
в группы КБТ. Электроника/Инструменты/Запчасти/Разное → в конец.

## Незакрытые баги (нужно исправить)

### 1. Сушильные машины не встают после Стиральных

**Причина:** `group_sort_key` проверяет `group_after` только когда группа **не найдена** в `group_order`. Но "Сушильные машины" есть в Excel-файле с порядком, поэтому `group_after` игнорируется.

**Фикс** — в `build_pricelist`, функция `group_sort_key`, проверять `group_after` **до** обращения к `group_order`:

```python
def group_sort_key(g):
    if g in _group_positions:
        return _group_positions[g]
    # group_after проверяем ПЕРВЫМ — переопределяет позицию из Excel
    if g in _group_after:
        parent = _group_after[g]
        parent_pos = group_order.get(parent) or group_order.get(parent.rstrip())
        if parent_pos is not None:
            return parent_pos + 0.5
    pos = group_order.get(g) or group_order.get(g.rstrip())
    return pos if pos is not None else max_order
```

### 2. Автовысота строк — текст наезжает

**Причина:** Делители в формуле слишком велики (24 для C, 85 для D) — высота занижена.

**Фикс** — в `build_pricelist`, строки расчёта высоты:

```python
brand_lines = max(1, math.ceil(len(str(item['brand'])) / 18))
name_lines  = max(1, math.ceil(len(str(item['name']))  / 60))
ws.row_dimensions[row].height = max(brand_lines, name_lines) * 15.5
```

### 3. Медная труба — проверить сортировку

Диагностика показала что из 52 расходников медь имеет `subsection_order=1`, дренаж `sub=5`, крепёж `sub=7`. Изоляция и кронштейны — **не парсятся** (sub=0?).

Нужно:
1. Запустить диагностику и вывести все 52 позиции с их `subsection_order` ДО и ПОСЛЕ сортировки
2. Убедиться что подсекции «Изоляция» и «Кронштейны» из СплитХаб-файла правильно распознаются в `read_splithub_price`
3. Скорее всего нужно добавить/поправить заголовки подсекций в `elif` внутри блока `if current_section == 'Расходники'`
