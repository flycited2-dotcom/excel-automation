# Хэндофф — Excel-автоматизация БытТехОпт

## Что сделано

- Интеграция прайса СплитХаб (`splithub-price.xlsx`) — 4 группы: Классические, Инверторные, Полупромышленные сплит-системы + Расходные материалы для монтажа (медь)
- Исключение групп `Кондиционеры инверторные` / `Кондиционеры он/офф` из основного прайса
- Цены СплитХаб — 1:1, без наценки
- Артикул = числовой ID из col B СплитХаб
- Наименование = модель (без дублирующих ключевых слов) + описание; DAICHI/DANTEX получают суффикс `(GREE)`
- Ширина столбца C = 22.5, wrap_text на C и D, автовысота строк
- Кастомная сортировка Расходников: первые 25 позиций по последовательности `[3,1,5,2,4,6,7,10,8,12,9,11,13,14,15,16,17,18,19,25,20,21,23,24,22]`
- `group_positions` в config — кондиционеры и расходники идут первыми (1.0, 1.3, 1.6, 2.0)
- `group_after` в config — Сушильные машины сразу после Стиральных

## Баннер в шапке прайса (готово)

- Картинка `banner.png` (сейчас = banner7 с вшитыми контактами) первой строкой шапки
- Привязка якорем `TwoCellAnchor` к диапазону A:F — правый край ровно по столбцу F
- `banner_aspect` в config (сейчас `4.88`) — центральная полоса картинки **обрезается** до этого соотношения (срез лишнего неба/полос), баннер во всю ширину но компактный (~163 pt). Это ОБРЕЗКА, не сжатие
- Опционально `banner_height_pt` — фикс. высота строки (вызывает сжатие картинки, **не использовать** для пропорциональной обрезки)
- Точная ширина столбцов в px по формуле Excel (`_table_px_width` = 1064)
- Контакты вшиты в баннер → текстовых строк (название/телефоны/город) в шапке НЕТ. Шапка: баннер → заголовки → товары
- Замена баннера: положить новый `banner.png` в корень (или сменить `banner_file` в config)
- Исходники баннеров — папка `Фото баннер для прайса/` (в gitignore)

## Незакрытые баги (нужно исправить)

### 1. Сушильные машины не встают после Стиральных

**Причина:** `group_sort_key` проверяет `group_after` только когда группа **не найдена** в `group_order`. Но "Сушильные машины" есть в Excel-файле с порядком, поэтому `group_after` игнорируется.

**Фикс** — в `build_pricelist`, функция `group_sort_key`, проверять `group_after` **до** обращения к `group_order`:

```python
def group_sort_key(g):
    if g in _group_positions:
        return _group_positions[g]
    # group_after проверяем ПЕРВЫМ — переопределяет позицию из Excel
    if g in _group_after:
        parent = _group_after[g]
        parent_pos = group_order.get(parent) or group_order.get(parent.rstrip())
        if parent_pos is not None:
            return parent_pos + 0.5
    pos = group_order.get(g) or group_order.get(g.rstrip())
    return pos if pos is not None else max_order
```

### 2. Автовысота строк — текст наезжает

**Причина:** Делители в формуле слишком велики (24 для C, 85 для D) — высота занижена.

**Фикс** — в `build_pricelist`, строки расчёта высоты:

```python
brand_lines = max(1, math.ceil(len(str(item['brand'])) / 18))
name_lines  = max(1, math.ceil(len(str(item['name']))  / 60))
ws.row_dimensions[row].height = max(brand_lines, name_lines) * 15.5
```

### 3. Медная труба — проверить сортировку

Диагностика показала что из 52 расходников медь имеет `subsection_order=1`, дренаж `sub=5`, крепёж `sub=7`. Изоляция и кронштейны — **не парсятся** (sub=0?).

Нужно:
1. Запустить диагностику и вывести все 52 позиции с их `subsection_order` ДО и ПОСЛЕ сортировки
2. Убедиться что подсекции «Изоляция» и «Кронштейны» из СплитХаб-файла правильно распознаются в `read_splithub_price`
3. Скорее всего нужно добавить/поправить заголовки подсекций в `elif` внутри блока `if current_section == 'Расходники'`

## Файлы

| Файл | Назначение |
|------|-----------|
| `transform.py` | Основная логика трансформации |

## Как запускать

```
python run.py                    # интерактивно
python run.py --immediate        # трансформация + сразу отправить
python run.py --send-at 10:00    # трансформация + отправить в 10:00
```

Входной файл кладётся в `input/`, берётся самый новый.
